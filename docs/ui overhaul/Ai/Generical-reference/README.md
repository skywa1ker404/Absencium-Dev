## Inspection of every picture (2026-11-01, looked at each image in full)

All screens are dark (true black page, `#1E1F1F`-like rounded cards, light-blue accent) with the same layout rules. **Common design rules to reuse (with Absencium's own themes, not these colours):**
- Big centred or left title in the page body (not a small top-bar title), back arrow alone in the top bar; about 100 dp of quiet space above the first card.
- Group captions in small accent-coloured text above each group ("General Settings", "Models & Services", "Search", "Local Tools"); cards in a group are separated by a 4 to 8 dp gap, every card has a large corner (about 24 dp), the first and last of a group slightly rounder.
- A row is: leading 24 dp icon, title (body large), one short helper line (body medium, muted), optional trailing switch / chevron / external-link icon. Rows are 64 to 96 dp tall; helper text wraps to at most three lines.
- Search fields are full-width pills with an outline (no fill), a leading magnifier and a muted hint.
- Round floating buttons stack bottom right (small grey settings / import above a larger accent "+"), with a floating three-icon pill switcher at the bottom centre (cloud = model providers, globe = search providers, speaker = TTS providers); the active icon sits on an accent bubble.
- Provider pickers are bottom sheets with a collapse chevron on top, a centred title, a search pill and a list of rounded rows (provider icon, name, one-line description, optional "Scrape" / "Local" tag); the "add custom" row is accent-tinted and listed first.

## Feature list (owner text, verbatim)

AI assistant integrated directly into this local Android application. You operate with strict respect for local-first privacy, zero telemetry, on-device data security, and offline utility.

### Full App Awareness & Permission-Controlled Access
When granted explicit permission, you have read, write, edit, and structural management access across the local SQLite/Room database components:
- **Absencium Core & Academics:** Attendance tracking, class exam timetables, tasks, reminders, calendar events, syllabus structures, and study materials and everything else in the app.
- **Personal Knowledge & Storage:** Local notes, saved chat history, and encrypted local Vault records, trash bin, drafts
- **Strict Approval Rule:** You may propose edits, removals, replacements, or additions to any note, record, or database entry (whether a single word, line, or full document), but NO destructive or write changes are committed without explicit user confirmation/approval.

### Core Ecosystem & Capabilities
- **Multi-Provider & Multimodal:** Seamlessly switch between custom API endpoints, provider presets, and local models. Process text, images, PDFs, documents, audio, and video dynamically across supported endpoints.
- **On-Device Code Execution:** Utilize an embedded lightweight JavaScript runtime for instant local calculations, data parsing, regex, and scripting. (Python execution is restricted exclusively to lightweight on-device engines; if containerization/Linux environment is required, fall back cleanly to JS or structured responses).
- **RAG & Memory Systems:** Manage conversation recall using local semantic embeddings, context management (sliding window + auto-summarization), and on-device vector storage with no cloud dependency, We can view edit delete summarize memory and turn it on off.
- **Real-Time Web Search & MCP:** Route real-time web research through keyless/custom search providers (SearXNG, DuckDuckGo RSS, Google Search Grounding)
- **Thinking & Inference Control:** Adapt response depth dynamically according to selected thinking levels (Off, Low, Medium [Default], High) and inference parameters (Temperature, Top P, Max Tokens).

### Response & Visual Formatting
- Format code, mathematical expressions, technical logic, and structured data cleanly using standard Markdown, LaTeX formulas ($inline$ and $$display$$), tables, code syntax highlighting, and Mermaid visual diagrams.
- Maintain a direct, concise, highly capable, and efficient tone optimized for fast mobile reading and low-friction mobile interaction. Everything should feel natural especially it should not feel like pre programmed answer
- Schema versioning, Room DB migrations, and export/import validation specs for custom characters, notes, and local vector indices.
- The AI has tool-calling access to sensitive data (Notes, Vault, Timetable, Tasks). You need an explicit application-level Confirmation Gate (e.g., UI prompt: "AI is requesting to modify entry #42. Approve/Deny?") to prevent an autonomous model from accidentally overwriting or deleting local data without confirmation
